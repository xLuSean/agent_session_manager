使用者從使用手冊開始；開發者先讀架構與安全規則，再依工作查閱開發指南或資料庫。驗收狀態不取代安全規則，也不是新的真實資料操作授權。

## 維護原則

- 同一項資訊只有一個主要來源：操作放手冊、規則放安全、結果放驗收、未完成工作放後續方向。
- 精確 API、版本准入與資料表定義以文件連結的程式為準；文件解釋用途與不可破壞的約束，不複製完整程式。
- 歷史實驗、逐次失敗、外部工具比較與舊研究由 Git 保留，不建立第二套現行文件。追溯入口見驗收狀態。
- 測資只保留現行測試需要的內容；舊階段、一次性確認文字與授權不當成永久測試需求，退役後由 Git 追溯。
- 不提交真實對話 ID、標題、私人路徑、設定 diff、備份或原始 provider 回應。
