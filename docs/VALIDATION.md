## 原始碼發布歷史整併

- 原開發分支的 42 筆提交先整理成 `fc3ba4c`，再 squash merge 為 `main` 的 `e28914d`；整併前後 Git tree 完全一致。已知含個資的舊開發提交與檔案物件不在整理後 `main` 的可追溯歷史中；目前文件亦不再包含該批私人路徑與真實對話識別碼。
- 依使用者決定保留 Codex 本機工作快照與 reflog，不執行先前準備的本機物件清理。保留本機復原資料不等於把它們納入 `main`；發布時只推送 `main` 及人工驗收後明確選定的標籤，不推送開發分支、特殊引用或 mirror。
- 歷史 commit 識別碼供辨認過去驗收來源；舊本機 DMG 仍保留原 manifest，不改寫成新來源。後續發布候選須從整理後的乾淨 `main` 重新建置，並人工確認確切成品；未連線核對 GitHub，也未 push。

- 版本工具新增單一 `Version.xcconfig`、patch 自 100 起算、獨立 build、plan／prepare／finalize、確切 Git 來源打包與 DMG／SHA-256／manifest 三件組。`--local` 候選不能當作公開候選 finalize；拒絕覆寫、篡改及不明 manifest 欄位。117 項腳本測試與 141 項 App 測試通過；Debug／Release 版本 metadata 讀回及 Release 出貨邊界檢查通過。標籤流程使用人工 repository 與假打包器驗證；後續已產生真實本機候選三件組，未建立本專案發布 tag 或操作 GitHub。

- 人工資料重現 macOS SQLite 在 WAL／SHM 缺少時，唯讀查詢回傳 `SQLITE_CANTOPEN`；這不等於結構不相容。
- 正常 SQLite 讀取保持不變；只有 CANTOPEN 且 WAL／SHM／journal 全部確定不存在時，才以 macOS `O_EXLOCK | O_NONBLOCK` 原子取得主檔獨占鎖，鎖內採單檔唯讀模式讀取結構。鎖定前後檢查路徑、檔案身分、變更時間及附屬檔；拿不到鎖、來源替換或附屬檔出現即停止。沒有建立附屬檔、改寫主檔、複製私人資料或放寬刪除權限。
- 測試涵蓋唯讀檔案／目錄、缺少附屬檔、現有 WAL 的新結構、跨程序鎖定、保留既有 SQLite 鎖、來源替換及 URI 特殊字元。相容性 log 增加數字系統錯誤及附屬檔狀態，不記錄內容或私人路徑。
- 暫時讀不到不再當成 Codex 更新；完成摘要列出通過／失敗／跳過數量，結構檢查和隔離測試時間分開標示。提醒入口改用正式 Settings scene，與 Logs 共用導覽，不再另開相容性 sheet。

### 隔離行為測試（第二階段原始碼，尚未打包）

## 保留的限制與設計決策

- 官方對話不存在、Desktop 殘留已清除、全域設定已清除是三種結果；Deleted 頁籤或單一 Success 不能代替全部證據。
- 掃描使用當下 canonical state 缺席與官方精確讀取缺席兩個訊號，不要求 Deleted witness、人工 Snapshot 或貼 UUID。不能讀取不等於已不存在。
- 使用者確認完整 Ghost 範圍一次，App 負責備份、重新驗證與執行。強制模式只擴充已知 session 摘要，不取消保護，也不修改自動化設定。
- 只有計畫準備前的資料庫占用可在關閉 Codex 後明確重新檢查；可能已執行、漂移或未知結果不自動重試。
- 全域設定 diff 是獨立確認。主檔與 `.bak` 各自原子更新，不是跨檔交易；中斷可能部分完成，備份保留，不自動還原。
- ASM 詳細完成紀錄與備份分開管理。全域設定備份目前不自動清除，含舊私人資料；不是安全抹除。
